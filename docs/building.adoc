== Building, flashing and CI

=== Toolchain

The *only supported build* is *CMake + the open AVR GNU toolchain*. The project
was migrated off Microchip Studio / XC8; no `.atsln`/`.cproj` files remain. The
required packages are:

[cols="1,3",options="header"]
|===
| Package | Why it is needed

| `cmake`         | Build system generator (>= 3.20).
| `avr-gcc`       | The cross-compiler (mainline avr-gcc).
| `avr-libc`      | Provides `<stdint.h>`, `<avr/io.h>`, `<util/delay.h>`, etc.
| `binutils-avr`  | `avr-objcopy` (hex generation) and `avr-size` (size report).
| `avrdude`       | Flashing the `.hex` onto the chip.
|===

On Fedora:

[source,sh]
----
sudo dnf install cmake avr-gcc avr-libc avr-binutils avrdude
----

[IMPORTANT]
====
*All packages are required.* In particular `avr-gcc` alone is not enough — without
`avr-libc` you will get `fatal error: stdint.h: No such file or directory`.
====

The compiler is *mainline avr-gcc*. (XC8 for AVR is a rebranded avr-gcc with
optimisation gated behind a licence; mainline removes that gate.) clang's AVR
backend is experimental and is not used.

=== Building the firmware

[source,sh]
----
cmake -B build -DCMAKE_TOOLCHAIN_FILE=cmake/avr-toolchain.cmake
cmake --build build
----

This produces:

* `build/Tuna.elf` — the linked firmware,
* `build/Tuna.hex` — Intel-HEX image for flashing, and
* `build/Tuna.map` — the linker map,

and prints a size report (`avr-size`) as a post-build step.

==== The AVR-Dx Device Family Pack

The AVR64DD14 is a newer AVR-DD part. Its runtime (crt, libdevice) and register
headers are *not* bundled with stock avr-gcc/avr-libc — they ship in Microchip's
*AVR-Dx Device Family Pack* (a `.atpack`, which is just a zip).

By default CMake *auto-downloads and extracts* the pack at configure time via
`FetchContent`, into `build/_deps/avr_dfp-src`. The version is pinned by
`AVR_DFP_VERSION` in `CMakeLists.txt` (currently `2.8.343`).

For an *offline build*, point CMake at a locally-extracted pack instead:

[source,sh]
----
cmake -B build -DCMAKE_TOOLCHAIN_FILE=cmake/avr-toolchain.cmake \
      -DAVR_DFP=/path/to/extracted/AVR-Dx_DFP
----

Configure fails fast if the supplied pack does not contain `gcc/dev/avr64dd14`.

=== Build options

[cols="1,2,2",options="header"]
|===
| CMake variable | Default | Effect

| `AVR_DFP`
| (empty → auto-download)
| Path to an extracted AVR-Dx DFP for offline builds.

| `AVR_DFP_VERSION`
| `2.8.343`
| DFP version fetched when `AVR_DFP` is unset.

| `PITCH_METHOD`
| (empty → `config.h` default)
| Override the pitch engine: `YIN` or `FFT`. Forwarded as
  `-DPITCH_METHOD_<value>`, which `config.h` honours over its own default. Used
  by CI to compile-check both paths without editing `config.h`.

| `AVRDUDE_PROGRAMMER`
| (empty)
| `avrdude -c` programmer id (e.g. `serialupdi`, `pkobn_updi`). Required for the
  `flash` target.

| `AVRDUDE_PORT`
| `usb`
| `avrdude -P` port (e.g. `usb`, `/dev/ttyUSB0`).
|===

==== Compiler/linker flags

The firmware is built size-optimised with link-time optimisation and section
garbage collection. Both the compile and link steps also carry the MCU flags
`-mmcu=avr64dd14 -B <dfp>/gcc/dev/avr64dd14` (shown as `${MCU_FLAGS}` below),
which select the device and its runtime from the AVR-Dx Device Family Pack:

* compile: `${MCU_FLAGS} -Os -flto -ffunction-sections -fdata-sections
  -funsigned-char -funsigned-bitfields -Wall -Wextra`
* link: `${MCU_FLAGS} -Os -flto -Wl,--gc-sections -Wl,--relax -Wl,-Map=Tuna.map`

The `.elf` is then linked against `libm` (`target_link_libraries(... m)`).
`-funsigned-char` matters: the font/coefficient tables and ADC handling assume an
unsigned plain `char`. `libm` is required because `spectral.c` and `pitch.c` use
`log()`.

[NOTE]
====
`double` is left at avr-gcc's default size. If frequency-analysis precision
regresses versus the old XC8 build, pass `-mdouble=64` to widen `double` to 64
bits. `<avr/io.h>` is used throughout instead of XC8's `<xc.h>`.
====

=== Flashing

The programmer id is board-dependent and must be supplied:

[source,sh]
----
cmake -B build -DCMAKE_TOOLCHAIN_FILE=cmake/avr-toolchain.cmake \
      -DAVRDUDE_PROGRAMMER=serialupdi -DAVRDUDE_PORT=/dev/ttyUSB0
cmake --build build --target flash
----

Example UPDI programmers: `pkobn_updi` (Curiosity/Xplained on-board),
`serialupdi`, `snap_updi`, `pickit4_updi`, `xplainedmini_updi`.

=== Continuous integration

GitHub Actions (`.github/workflows/ci.yml`) runs on pushes to `develop`, on pull
requests, and on manual dispatch. It has two jobs:

[cols="1,3",options="header"]
|===
| Job | What it does

| `host-tests`
| Configures `test/`, builds the host DSP regression tests with the native
  compiler, and runs them with CTest. No AVR toolchain involved — the
  fixed-point DSP runs bit-for-bit identically on host and target.

| `firmware`
| A matrix over `pitch: [YIN, FFT]`. Installs the AVR toolchain
  (`gcc-avr avr-libc binutils-avr`), caches the AVR-Dx DFP under `build/_deps`,
  cross-compiles the firmware for the AVR64DD14 with
  `-DPITCH_METHOD=<pitch>`, writes a size report to the job summary, and uploads
  `Tuna.hex` / `Tuna.elf` / `Tuna.map` as artifacts.
|===

Both pitch paths are compile-checked on the real toolchain every run. Keep new
DSP behaviour covered by a `test/` case where practical.

=== Gitignored artifacts

`build/`, `[Dd]ebug/`, `[Rr]elease/`, `external/` (a locally-extracted DFP), and
build results (`*.o`, `*.d`, `*.eep`, `*.elf`, `*.hex`, `*.map`, `*.srec`) are
gitignored.
